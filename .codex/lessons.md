# 项目防错记录

## 2026-11-06：修改落盘与实际验证

- 根因：Node REPL 跨 cell 的编辑 helper 捕获旧变量，后续同名绑定未进入闭包，造成只保存了部分修改。
- 缺失检查：只做语法检查，没有从磁盘核对关键函数与 DOM 是否已更新。
- 防错规则：编辑采用 (source, from, to) -> newSource 的纯函数并显式赋值，及时落盘；每阶段重新读盘核对后再报告完成。REPL 禁止动态编译时，用外部 Node 或浏览器验证语法，不使用 new Function。

## 2026-11-06：输入和技能回归

- 根因：浏览器虚拟时钟在游戏启动后安装，重置 performance 时间基准，使首帧产生负 delta；此为测试脚手架问题。
- 缺失检查：没有在加载页面前建立统一测试时钟。
- 防错规则：时钟必须先安装再导航，暂停时采用页面自身 Date.now；反向移动测试应覆盖加减速过程，不能假定输入立即反转速度。
- 技能状态必须同时覆盖移动、投掷、抢断、自动拾取、扑救和飞贼捕获；不能仅停止移动就认为完成击晕逻辑。
- 检查镜头准星与技能锁定是否共用屏幕射线，射程仍按玩家与目标距离判断；追踪弹寿命需覆盖射程边缘的移动目标。
- 本机受限 PowerShell 可能初始化失败，优先使用 cmd.exe（login:false）或 Node 读写。Godot 验证显式将日志写到工作区，避免 user:// 日志权限崩溃。

## 2026-11-06：完整体验与并行实现

- 根因：开始时未先读取本文件，重复使用了已知无法初始化的 PowerShell；随后把带引号的长 Node 表达式交给 cmd，触发参数转义错误。
- 缺失检查：没有先确定本机执行入口与既有防错记录。
- 防错规则：本项目命令优先 cmd.exe + login:false；复杂脚本保存为文件后执行，文件读写可用 Node REPL；重新进入工具会话时重新初始化绑定，不依赖上一会话的变量。
- 根因：大型玩法函数分段落盘时，旧 HUD 仍引用已移除状态，测试读到了中间版本。
- 缺失检查：模块接口替换未做全文件旧标识搜索，未通知测试方可开始验收。
- 防错规则：状态变量迁移后搜索全部旧引用；完成一个可启动版本后再发“可测”通知。代码语法通过不等于游戏已能启动。
- 静态合批必须仅发生在角色生成前，并保持原 castShadow / receiveShadow；透明、旗帜和其他动态对象不得合批。
- 真实用户式手感验收与浏览器自动化回归应分别记录；交互工具不可用时不得把脚本或截图称为人工连续游玩。

## 2026-11-09：先解决看清和跟上的问题

- 根因：把用户“难摸到球”过早理解为需要自动追球；实际问题是球速、转向和画面干扰，增加自动辅助不能解决根因。
- 缺失检查：没有先按“能否看见球、能否转过去、能否跟上、能否接住”分别验证完整操作过程。
- 防错规则：体验问题先复现感知与操作链。优先修正球速、平滑转向、场景遮挡和持续球位提示；避免用自动操作替代用户要求的手感改善。
- 根因：新增全局 targetYaw 后，updatePlayer 内保留同名局部变量，引发暂时性死区错误；语法检查无法发现该运行时问题。
- 缺失检查：修改输入状态时未先检查同名局部变量和非游玩阶段的输入更新。
- 防错规则：目标角与模型朝向分别命名；验证菜单启动、倒计时转向、游玩转向与暂停恢复。平滑处理必须覆盖所有接受输入的阶段。
- 降低传球速度后同时检查接收者速度和接球窗口；向玩家回传明确提示减速接球，并验证真实 W → T → X 操作，避免慢球永远追不上持续远离的玩家。
