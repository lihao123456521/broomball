# 核心足球玩法重构

## 新的比赛契约

常用键集中在左手：WASD移动，E短传，R直塞，F进攻蓄力射门/防守按住逼抢，Shift冲刺，Esc暂停。没有额外动作键、鼠标瞄准、手动升降、切人、切镜头、魔法或商城升级。标准与挑战均180秒，进球计1球，失球方开球；挑战只改变对方逼抢强度。

我方真实持球者具有最高控制权，包含守门员。传球飞行期间保留原控人，真实接球时立即接管接球人。对手取得球权时立即选最近可用我方场上防守者；持续防守使用0.35秒和1.75~4米距离优势防抖，不选择对手，也不移动任何实体。守门员通常留在门前，成为唯一可用防守者时才回退选择。

F按下时记录攻防动作。失球取消蓄力并进入防守，抢回球后松开F不产生幽灵射门。真实keeper持球安全，等待用户E/R/F出球，避免被贴身AI反复夺走再射回所造成的镜头来回切换。角色与门将职责随实体保留，分球后仍仅有一个原始守门员。

传球继续使用可达落点和固定低弧。拦截、接收与自由球拾取都在真实持球手附近按1.35米判定；球靠近后才进入0.14秒收球。没有升降键时，低位自由球会触发自动高度接应，角色可平滑降低至接球范围，不在4米外吸球。控人切换不移动身体。

## 结构重做

`index.html`从包含完整脚本与大量内联样式的页面改为只含核心页面结构的入口。比赛协调移入`game-core.js`；键位、自动换控、球路、纯球员数据、单一默认装备分别由`game-controls.js`、`game-team-control.js`、`game-passing.js`、`game-roster.js`、`game-rider-gear.js`负责。首页和HUD拆为`game-core-ui.css`/`game-core-hud.css`。

当前入口不加载旧主动技能引擎、商城、升级或Lux模型大块内嵌数据。兼容的`SchoolMagic`和`BroomGarage`名称只指向纯角色数据与默认GLB挂载，不包含技能/商城函数。实测`createSchoolSpellEngine`和`initBroomShop`均为undefined。

保留7个上传GLB的真实实例：主堡、双侧尖塔、石桥门楼、外围城墙、所有球员默认赛用扫帚、场边奖杯、Harry完整骑乘角色。模型加载7/7，实际placements均非空；错误和外部请求均空。既有Joanna en-GB女性英语本地赛事录音继续使用，不产生新语音请求。

低球额外证据：角色从10米平滑降到约1.72008米，手部真正进入2米高度球的1.35米范围才拾取；最大单帧身体位移0.096米，其它身体位移0。门将贴身保护后E真实分球，控制者恢复场上队员，唯一Keeper仍为原物理mesh。

中途发现并修复了旧基础CSS移除后的比分栏缺失定位、800窗口雷达top残留和终场按钮错位；已查看两尺寸攻防、暂停、终场8张最终截图。也发现自然比赛Keeper被连续夺球/射回导致32次闪控的问题，修复后复查为4次正常换控。
